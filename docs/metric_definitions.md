# 指标口径说明（Metric definitions）

所有指标都在 `sql/` 中计算，这里写清楚每个指标"怎么算、为什么这么算"。口径一旦改动，先改这份文档，再改 SQL。

## 订单范围

| 概念 | 口径 | 说明 |
|---|---|---|
| 有效订单 | `order_status` 不属于 `canceled`、`unavailable` | 已取消或缺货的订单不计入交易额 |
| 下单日期 | `order_purchase_timestamp` 的日期部分 | 所有日指标都按下单日归属 |
| 用户 | `customer_unique_id` | Olist 的 `customer_id` 每笔订单都会变，只有 `customer_unique_id` 才代表同一个人 |
| 分析窗口 | 2017-01-05 至 2018-08-21 | 2017-01-05 之前几乎没有订单；2018-08-22 之后的数据还没采集完整，订单量逐日下滑，会让监控产生误报 |

## 交易指标（`ads_daily_metrics`）

| 指标 | 字段 | 计算方式 |
|---|---|---|
| GMV | `gmv` | 有效订单的商品金额之和（`order_items.price`），不含运费 |
| 订单量 | `orders` | 有效订单数 |
| 下单用户数 | `buyers` | 有效订单的去重 `customer_unique_id` 数 |
| 客单价（AOV） | `aov` | GMV ÷ 订单量 |
| 取消率 | `cancel_rate` | 取消订单数 ÷ 全部订单数 |
| 差评率 | `bad_review_rate` | 评分 ≤ 2 的订单数 ÷ 有评分的订单数 |
| 延迟送达率 | `late_rate` | 实际送达晚于预计送达的订单数 ÷ 已送达订单数 |

日历表补齐了没有订单的日期（记为 0），否则系统故障导致的"零订单日"会直接从表里消失，监控就发现不了。

## 异常预警规则（`src/monitor.py`）

- 每个指标和**前 28 天**（不含当天）的均值、标准差比较，计算 z 值。
- |z| > 3 记为一次预警，并标注方向（上升或下降）。
- 当天不进入基线，避免异常值把自己"拉平"。
- 局限：没有单独处理周内效应，节假日和大促一定会触发预警。这是有意保留的——大促当天本来就应该被看到，复盘时再区分"预期内"和"预期外"。

## 活动复盘（`src/campaign.py`）

- 活动周：2017-11-20 至 2017-11-26（包含 11-24 黑色星期五）。
- 基线：活动前 4 周（2017-10-23 至 2017-11-19）的周均值。
- 拆解公式：GMV = 下单用户数 × 人均订单数 × 客单价。两边取对数后，三个因素的变化相加等于 GMV 的变化，每个因素的贡献 = ln(因素比值) ÷ ln(GMV 比值)。
- 品类贡献：活动周 GMV 减去基线周均 GMV，得到每个品类的增量。

## 送达时效与评价（`ads_delivery_review`）

- 只比较已送达且有评分的订单，按是否晚于预计送达分为两组，比较平均分和差评率。

## 评价与复购（`ads_review_repurchase`）

- 以每位用户的**第一笔有效订单**的评分分组，统计之后是否再次下单。
- 局限：越晚首购的用户，可观察的回购时间越短，复购率会被低估。这里比较的是不同评分组之间的相对差异。
